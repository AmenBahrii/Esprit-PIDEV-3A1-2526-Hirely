1. Static analysis / PHPStan

For this criterion, I added two kinds of static analysis.

First, I created 8 custom forum static checks in:
tools/forum_static_checks.php

These checks verify important project rules:
- PHP files have valid syntax.
- No debug output like dd(), dump(), var_dump(), or print_r() is left in forum code.
- SQL is kept inside repositories instead of controllers/services.
- Controller render() calls point to existing Twig templates.
- Mutating forum routes like like/delete/comment use POST.
- Key forum classes can autoload correctly.
- AI integrations have fallback paths instead of crashing.
- Forum list pages paginate Doctrine queries instead of loading full arrays first.

Second, I installed and configured real PHPStan:
- phpstan/phpstan
- phpstan/phpstan-symfony
- phpstan/phpstan-doctrine

The configuration is in:
phpstan.neon.dist

I run:
vendor\bin\phpstan analyse -c phpstan.neon.dist

Current result: PHPStan passes at level 5 with Symfony and Doctrine extensions, with no broad ignore file or baseline hiding the problems.

Dependency cleanup explanation

Before, some bundles were manually downloaded as folders. I removed those folders and replaced them through Composer:
- KnpPaginatorBundle -> knplabs/knp-paginator-bundle
- AntiSpamBundle -> omines/antispam-bundle
- DoctrineFixturesBundle -> doctrine/doctrine-fixtures-bundle
- DoctrineDataFixtures -> doctrine/data-fixtures

doctrine/data-fixtures is installed automatically because doctrine/doctrine-fixtures-bundle depends on it.
